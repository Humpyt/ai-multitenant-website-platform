# App Flow Document

## Onboarding and Sign-In/Sign-Up
New users start their journey on the public landing page, where they are invited to either sign in or create an account. Clicking the sign-up link opens a form asking for an email and password. Once these fields are filled and submitted, the app creates a new user record, initializes a tenant profile behind the scenes, and immediately redirects the user into the onboarding experience. If the user already has an account, they click the sign-in link, enter their credentials, and are taken directly into their dashboard. A “Forgot your password?” link on the sign-in form leads to a recovery page where the user submits their email, receives a reset link via email, and then sets a new password. At any point during an active session, the user can click a “Sign out” button in the header to end the session and return to the landing page.

## Main Dashboard or Home Page
After signing in, the user lands on a protected dashboard page. The top of the screen features a header with the application logo, a theme toggle switch for light or dark mode, a notifications icon, and an avatar menu that includes a sign-out option. On the left side, a vertical navigation panel lists links for Dashboard, Create New Site, Site Editor, and Settings. The main content area displays cards for each tenant website, showing the site's name, domain, status, and quick actions like preview or open editor. A prominently placed button invites the user to start the onboarding wizard for a new site.

## Detailed Feature Flows and Page Transitions
When the user clicks the Create New Site button in the navigation or on the dashboard, they enter the multi-step BusinessSetupWizard. The wizard is broken into sequential screens that collect business details, branding preferences, domain selection, and optionally billing information for subscription setup. The user moves forward and backward between steps without losing entered data. On the final step, submitting the form sends a request to the backend endpoint for tenant creation. The application then shows a progress screen that polls the generate-website API until the AI engine completes the site. Once the AI has generated HTML, CSS, and JavaScript and stored it in the user’s S3 bucket, the user is automatically redirected to a Site Overview page for that tenant. On that overview page, they see a live preview of their new website and a button to open the in-browser editor. The editor page splits the view into a code editor pane and a live preview pane. Any changes are saved in real time through a PUT request to the website API and immediately reflected in the preview.

The payment process is seamlessly woven into the onboarding flow. If the user’s chosen plan requires immediate payment, submitting the wizard redirects them to a payment page with an embedded Flutterwave checkout widget. Upon successful payment, the user sees a confirmation screen and is then routed back to the dashboard. Meanwhile, a secure webhook endpoint on the backend listens for payment events to update the tenant’s subscription status.

## Settings and Account Management
Users can manage their personal and billing information by clicking the Settings link in the sidebar. The settings page presents separate sections for Profile, Billing, and Preferences. In the Profile section the user can update their name, email, and password, or upload a new avatar. The Billing section shows the current subscription plan, next billing date, and provides buttons to upgrade, downgrade, or cancel the plan. The Preferences section lets the user toggle notification settings and switch between light and dark themes. Changes are saved with a simple form submit, and the user can then use the navigation menu to return to the dashboard or any other part of the app.

## Error States and Alternate Paths
If the user enters invalid credentials on sign-in, the login form displays a clear error message beneath the input fields. Accessing any protected route without a valid session automatically redirects the user back to the sign-in page. Within the onboarding wizard, form validation prevents proceeding with incomplete or invalid data and highlights the exact field needing correction. If a domain chosen for a tenant is already in use, the wizard shows a friendly error screen explaining the conflict and suggests trying a different domain. During site generation or saving edits in the editor, network failures cause a banner to appear at the top of the page with options to retry the action. Payment failures return a screen with details from the payment provider and a button to retry checkout. If the user navigates to an undefined route, they land on a custom 404 page that offers a link back to the dashboard or home.

## Conclusion and Overall App Journey
The application guides a new user from the moment they arrive on the landing page through account creation, tenant setup, AI-driven site generation, and payment, all the way to daily site management and editing. At each step, clear navigation and consistent UI elements help the user understand where they are and what to do next. Whether they are starting a brand-new site, updating content, or adjusting their account settings, the flow remains coherent and intuitive, supporting the user’s goal of quickly creating, paying for, and maintaining multi-tenant websites powered by AI.
